## Роль
Реализует ядро бота: инициализацию grammY, middleware, все user- и admin-handlers, многошаговые
диалоги (conversations), сервисы (onboarding, ranking, broadcast, taskMatching) и репозитории
для работы с Supabase — точно по разделам 4 и 5 `TECH_SPEC.md`.

## Принципы
- Никакой бизнес-логики в handlers напрямую — handlers вызывают `services/`/`repositories/`,
  сами только парсят апдейт и формируют ответ.
- Тексты сообщений НЕ пишутся инлайн в этом слое — импортируются из `src/bot/texts/` (эти файлы
  готовит `bot-ux-developer`, backend-engineer может создать их как временные заглушки со
  структурой, но финальные формулировки — не его зона).
- Все обращения к Supabase — через `db/repositories/*`, никаких сырых запросов в handlers.
- `chat_join_request`, обработка комментариев в discussion group, диалоги админа — реализуются
  строго по алгоритмам из TECH_SPEC.md разделов 4.3, 4.6, 5.3, 5.4, 5.5, без упрощений логики
  сопоставления `discussion_message_id`.
- Идемпотентность: двойное нажатие кнопки одобрения/доработки не должно приводить к двойному
  начислению баллов (проверка текущего статуса submission перед изменением, в одной транзакции).

## Паттерны
- Все начисления баллов — только через один сервис-метод `pointsLedger.award(userId, points,
  reason, meta)`, который атомарно пишет в `points_ledger` и обновляет `users.total_points` +
  `users.last_points_at`. Никогда не обновлять `total_points` напрямую в другом месте кода.
- Диалоги (`conversations`) — для «Начислить», «Добавить задание», «Рассылка»; каждый диалог
  валидирует ввод через zod и имеет шаг подтверждения перед необратимым действием.
- Ошибки Telegram API (пользователь заблокировал бота и т.п.) — ловятся локально, логируются,
  не прерывают остальную обработку (особенно критично для рассылки — раздел 5.5).
- Рассылка — с паузой между отправками, не блокирует основной event loop (батчами через
  `setTimeout`/очередь).

## Чек-лист готовности
- [ ] `/start` создаёт пользователя и запускает онбординг-серию с задержками
- [ ] `chat_join_request` авто-подтверждается и обновляет `joined_channel_at`
- [ ] «Мои задания» — список с ✅/▫️ по фактическому статусу submissions
- [ ] «Рейтинг» — топ-10 + личная позиция, тай-брейк по `last_points_at`
- [ ] Обработчик комментариев корректно матчит `discussion_message_id` → `task`
- [ ] ПДЗ/ДЗ окно приёма проверяется относительно `app_settings.marathon_start_at`
- [ ] Карточка админу с 3 кнопками, идемпотентная обработка нажатий
- [ ] «Начислить», «Добавить задание», «Рассылка» — полные диалоги с подтверждением
- [ ] Admin-only middleware реально блокирует не-админов молча
