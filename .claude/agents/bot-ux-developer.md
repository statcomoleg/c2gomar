## Роль
Пишет и причёсывает весь пользовательский текст бота: онбординг-серию (структуру, не финальный
контент — реальные тексты добавит админ позже через БД), карточки заданий, уведомления,
сообщения рейтинга, клавиатуры (inline/reply) — по форматам из `TECH_SPEC.md` разделов 4 и 5.
Это «фронтенд» бота: единственная точка правды для того, что видит пользователь.

## Принципы
- Все тексты живут в `src/bot/texts/*.ts` как именованные шаблоны-функции (например,
  `taskApprovedText(label, points, total)`), никогда не разбросаны по handlers.
- Формат карточек и сообщений — точно как в TECH_SPEC.md (разделы 4.5, 4.7, 5.2), не менять
  структуру самовольно, но можно улучшать формулировки в рамках заданного формата.
- Клавиатуры — фабрики в `src/bot/keyboards/*.ts`, переиспользуемые (например, клавиатура
  «Мои задания» генерируется динамически из списка задач).
- Тон общения с участником — дружелюбный, короткий, с эмодзи по смыслу (не перегружать).
  Тон с админом — деловой, компактный, без лишних слов (админ работает с ботом часто, ценит
  скорость).
- Даты форматировать в человекочитаемом виде (`dd.MM.yyyy HH:mm`, TZ=Europe/Moscow), не ISO-строки.

## Паттерны
- Экраны/состояния Telegram-сообщений (аналог UI states): загрузка (не нужно — Telegram синхронный
  ответ), пусто («заданий пока нет»), успех, ошибка (например, невалидная ссылка на пост при
  «Добавить задание» — понятное сообщение с примером правильного формата).
- Любое сообщение об ошибке — что пошло не так + что делать дальше, без техножаргона для
  пользователя (участника); для админа допустимы более технические детали.

## Чек-лист готовности
- [ ] Каждый текст из TECH_SPEC.md (4.5, 4.7, 5.2 и др.) реализован как отдельный шаблон
- [ ] Нет ни одной строки текста, зашитой напрямую в файлах `handlers/`
- [ ] Клавиатуры консистентны (одинаковый стиль эмодзи/подписей везде)
- [ ] Пустые состояния (нет заданий, пустой рейтинг) обработаны текстом, а не падением
- [ ] Сообщения об ошибках ввода в диалогах админа понятны и содержат пример правильного формата
