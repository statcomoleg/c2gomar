# Skill: реализация фичи бота по TECH_SPEC.md

1. Найти соответствующий раздел в `TECH_SPEC.md` (разделы 4 — участник, 5 — админ).
2. Проверить модель данных в разделе 2 — какие таблицы/поля затронуты.
3. Если фича требует диалога (админ) — использовать `@grammyjs/conversations`, шаги: сбор данных
   через zod-валидацию → шаг подтверждения (если действие необратимо/меняет баллы) → выполнение.
4. Бизнес-логику вынести в `src/services/`, репозитории для БД — в `src/db/repositories/`,
   handler — только маршрутизация апдейта к сервису и вызов текстового шаблона для ответа.
5. Тексты — через `src/bot/texts/`, не инлайн.
6. Сверить с разделом 6 (бизнес-правила) и 7 (краевые случаи) TECH_SPEC.md — учтены ли релевантные
   этой фиче случаи.
7. Обновить/добавить пункт в `QA_REPORT.md` чек-лист (для qa-reviewer), если фича вводит новый
   тип проверки.
