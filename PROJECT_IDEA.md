# PROJECT_IDEA — Telegram-бот для марафона «Контент-завод»

## 1. Проблема

- Организатор онлайн-марафона (практикум по профессии контент-креатора) вручную вовлекает
  аудиторию: пишет приветственные сообщения, следит за заявками на вступление в закрытый канал,
  вручную читает каждый комментарий-отчёт под постами с заданиями, вручную считает баллы и
  составляет рейтинг. При потоке в 50–300+ участников это отнимает несколько часов в день и
  провоцирует ошибки (забыл начислить балл, потерял отчёт в ленте комментариев).
- Без геймификации (баллы, рейтинг) вовлечённость и процент выполнения заданий участниками падает.
- Нужен инструмент, который: (1) автоматически ведёт пользователя от первого касания до вступления
  в канал, (2) отслеживает комментарии-отчёты и присылает их админу на модерацию одной кнопкой,
  (3) начисляет баллы и ведёт рейтинг автоматически, (4) даёт админу быструю рассылку по базе.

## 2. Решение

Telegram-бот с двумя ролями интерфейса — **участник** и **админ**:

- Участник: серия онбординг-сообщений → вступление в закрытый канал по заявке → в канале посты с
  предварительными (ПДЗ) и основными (ДЗ) заданиями → отчёт пишется комментарием под постом →
  бот пересылает админу на проверку → участник получает уведомление об одобрении (+баллы) или
  отправке на доработку → в любой момент участник смотрит статус всех своих заданий и рейтинг.
- Админ: заранее заводит задание в боте (тип, краткое описание, ссылка на пост) → бот сам находит
  комментарии под этим постом и присылает админу карточку заявки на проверку с кнопками
  «На доработку» / «+3 балла» / «+10 баллов» → админ также может вручную начислить баллы и
  сделать рассылку (всем или по критерию рейтинга).

## 3. Аудитория

- **Участники марафона** — пользователи Telegram, заинтересованные в обучении контент-креаторству,
  проходят марафон через закрытый канал + группу обсуждений (комментарии).
- **Админ(ы) марафона** — организатор(ы)/кураторы, которые публикуют посты в канале, проверяют
  задания и управляют ботом. Может быть несколько админов (список Telegram ID в конфиге).

## 4. Архитектура (высокоуровнево)

- **Бот**: Node.js + TypeScript, фреймворк **grammY** (long polling, без вебхуков — проще для
  старта и деплоя без домена/SSL).
- **База данных**: **Supabase (Postgres)** — таблицы users, tasks, submissions, points_ledger,
  onboarding_messages. Доступ из бота через service-role ключ (бот — единственный клиент БД,
  RLS включён как defense-in-depth, но основная защита — на уровне кода бота).
- **Хостинг бота**: Railway или Render — обычный Node-процесс с long polling, автоперезапуск.
- **Интеграция с Telegram**: бот является админом и в самом канале, и в привязанной группе
  обсуждений (discussion group) — без этого он не увидит ни заявки на вступление, ни комментарии.
- **Без веб-интерфейса** в MVP — всё управление через кнопки и диалоги внутри самого бота.

## 5. Монетизация

Не применимо к MVP — бот является внутренним инструментом администрирования марафона,
не продуктом с прямой монетизацией. (Если в будущем потребуется платный вход в марафон —
это отдельная фича, в MVP не включена, см. «Вне рамок MVP».)

## 6. Конкуренты / аналоги

- Ручное администрирование через таблицы Google Sheets + вручную читаемые комментарии (то, что
  сейчас использует организатор — медленно, не масштабируется).
- Готовые платформы геймификации курсов (GetCourse, Skillspace и т.п.) — избыточны, дорогие,
  не заточены под механику «канал + комментарии + Telegram-бот».
- Ключевое отличие данного бота: нативная интеграция с уже существующей аудиторией в Telegram-
  канале, без переноса пользователей на сторонние платформы.

## 7. План запуска

1. Развернуть Supabase-проект, применить SQL-миграции (схема — см. TECH_SPEC.md).
2. Создать бота через @BotFather, получить токен, сделать бота админом канала и группы обсуждений.
3. Задеплоить бот-процесс на Railway/Render с переменными окружения.
4. Админ через кнопку «Добавить задание» заводит ПДЗ-1, ПДЗ-2 и т.д. до старта марафона.
5. Бот запускает онбординг-серию для новых пользователей, ведёт к заявке на вступление в канал.
6. После старта марафона админ переключает публикацию на ДЗ (см. бизнес-правило в TECH_SPEC.md).

## 8. Риски

| Риск | Пояснение | Митигация |
|---|---|---|
| Бот не видит комментарии | Discussion group не привязана к каналу, либо бот не админ в группе | Явный чек-лист в README при деплое |
| Дублирование отчётов | Пользователь пишет несколько комментариев под одним постом | Бот создаёт новую submission на каждый комментарий, админ видит историю, старые пере-отправки помечаются как «заменено» |
| Флуд при рассылке | Telegram ограничивает скорость отправки (~30 msg/sec) | Очередь рассылки с задержкой между сообщениями (см. TECH_SPEC.md) |
| Админ один — узкое горлышко проверки | Все отчёты идут одному человеку | Список ADMIN_TELEGRAM_IDS поддерживает нескольких админов, любой может обработать заявку |
| Дата старта марафона захардкожена неверно | ПДЗ/ДЗ логика завязана на MARATHON_START_DATE | Значение читается из конфигурации/БД, а не из кода, админ может изменить |

## 9. Технические детали и допущения по умолчанию

Ниже — решения, принятые по умолчанию, чтобы AI-агент не останавливался и не спрашивал очевидное.
Если что-то не подходит — измените явно перед стартом сборки.

1. **Заявки на вступление в канал одобряются автоматически** ботом (`chat_join_request` →
   auto-approve). Ручного шага «админ вручную нажимает одобрить в Telegram» нет — бот и так
   является админом канала и может подтверждать заявки мгновенно.
2. **Онбординг-серия сообщений** (тексты, которые видит пользователь до вступления в канал)
   хранится в таблице `onboarding_messages` (порядковый номер, текст, задержка перед отправкой
   следующего). Тексты добавляет админ позже — бот поддерживает произвольное количество шагов.
3. **Сопоставление «комментарий → задание»**: работает через встроенный механизм Telegram
   Discussion Groups. Когда админ публикует пост в канале, Telegram автоматически пересылает
   его копию в привязанную группу обсуждений. Комментарии пользователей — это replies на эту
   пересланную копию. Бот при добавлении задания сохраняет `channel_message_id`, а затем
   при появлении в discussion-группе пересланного сообщения с таким `forward_from_message_id`
   запоминает его как `discussion_message_id` этого задания. Все входящие сообщения в группе,
   являющиеся `reply_to_message` на этот `discussion_message_id` (напрямую или через тред),
   считаются отчётами по этому заданию.
4. **Баллы за одобрение** — фиксированные пресеты **+3** и **+10** (по ТЗ), плюс админ отдельно
   может начислить любое произвольное количество баллов через кнопку «Начислить».
5. **Тай-брейк рейтинга**: при равном количестве баллов выше тот, кто раньше **достиг** этой суммы
   (по времени последнего начисления, из `points_ledger`, по возрастанию — раньше = выше).
6. **Пересдача после «на доработку»**: пользователь может отправить новый комментарий под тем же
   постом; создаётся новая запись submission со статусом `pending`, предыдущая — `superseded`.
7. **ПДЗ vs ДЗ**: ПДЗ можно сдавать только **до** `MARATHON_START_DATE`; после — новые submissions
   по ПДЗ автоматически отклоняются с уведомлением «приём предварительных заданий завершён».
   ДЗ становятся доступны для сдачи только **после** этой даты.
8. **Rate limit рассылки**: сообщения отправляются пачками с паузой ~35–50 сообщений/сек с запасом
   (Telegram лимит ~30/сек глобально, разумный запас — безопаснее).

## 10. Вне рамок MVP (сознательно не делаем сейчас)

- Веб-панель администратора (всё через сам бот).
- Оплата участия / подписки (Stripe и т.п.).
- Автоматическая проверка заданий через AI (проверка всегда человеком-админом).
- Мультиязычность интерфейса бота (только русский).
