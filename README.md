# Как пользоваться этим набором файлов (для тебя, без технического жаргона)

## Что тут лежит
Это полный пакет документов по методологии «5 слоёв AI-разработки»: от идеи до готового бота.
Всё уже написано и продумано — тебе не нужно ничего досочинять, только выполнить шаги ниже.

- `PROJECT_IDEA.md` — идея, зачем бот, какие решения приняты по умолчанию
- `TECH_SPEC.md` — подробное ТЗ: база данных, все кнопки, все сценарии, все тексты-форматы
- `CLAUDE.md` — главный конфиг для AI (структура репозитория, правила работы)
- `.claude/agents/*.md` — 4 «специалиста» (архитектор БД, бэкенд, тексты/кнопки, QA)
- `.claude/rules/*.md` — правила, которые AI обязан соблюдать при написании определённых файлов
- `.claude/skills/*.md` — повторяемые инструкции («как добавить фичу», «как сделать миграцию»)
- `MASTER_PROMPT.md` — **вот этот файл вставляешь в Cursor**, чтобы всё собралось

## Шаги

### 1. Создай пустой проект
Создай новую пустую папку на компьютере, открой её в Cursor (File → Open Folder).

### 2. Перенеси файлы
Скопируй ВСЕ файлы и папки из этого пакета (включая скрытую папку `.claude/`) в корень
твоей новой папки проекта. Так AI сразу увидит готовую спецификацию и не будет её выдумывать
заново.

### 3. Открой чат с AI-агентом в Cursor
Открой Composer/Agent-чат (обычно Ctrl+I или Cmd+I, режим Agent, модель — Claude, лучше Opus
или Sonnet последней версии).

### 4. Вставь содержимое MASTER_PROMPT.md
Открой файл `MASTER_PROMPT.md`, скопируй весь текст, вставь в чат агента и отправь.
Это одна команда — дальше агент сам создаст структуру проекта, миграции, весь код бота, тексты
и клавиатуры, и прогонит самопроверку по QA-чек-листу.

### 5. Дождись завершения
Это большая задача — дай агенту работать, не прерывай на середине. Если Cursor спросит
разрешение на выполнение команд (npm install и т.п.) — разрешай.

### 6. После того как код готов — твои ручные шаги (это не может сделать AI за тебя)
1. Создай проект в Supabase (supabase.com) — бесплатно.
2. Скопируй `SUPABASE_URL` и `service_role` ключ из настроек проекта.
3. Примени миграции из `supabase/migrations/` (Cursor подскажет команду, обычно
   `supabase db push` или через SQL Editor в интерфейсе Supabase — просто скопировать
   содержимое каждого файла миграции по порядку и выполнить).
4. Создай бота через @BotFather в Telegram, получи `BOT_TOKEN`.
5. Создай Telegram-канал (закрытый) и группу обсуждений, привяжи группу к каналу
   (в настройках канала: Discussion → Add group). Добавь бота админом И в канал, И в группу.
6. Узнай `channel_id` и `discussion_group_id` (числа, обычно отрицательные) — можно через
   пересылку любого сообщения из канала/группы боту @userinfobot либо попросить AI-агента
   добавить временный debug-хендлер, который выводит id в консоль.
7. Заполни строку в таблице `app_settings` реальными `channel_id`, `discussion_group_id`,
   `marathon_start_at` (дата и время старта марафона).
8. Заполни `.env` (скопируй из `.env.example`) реальными значениями BOT_TOKEN, SUPABASE_URL,
   SUPABASE_SERVICE_ROLE_KEY, своим Telegram ID в ADMIN_TELEGRAM_IDS.
9. Запусти бота (`npm start`), напиши ему `/start` — проверь, что всё работает.
10. Задеплой на Railway или Render (обычный Node-процесс, те же переменные окружения) —
    попроси AI-агента подготовить инструкцию под конкретный сервис, если нужно.

## Если что-то пошло не так
Просто вернись в чат с агентом и опиши проблему — вся спецификация (`TECH_SPEC.md`) уже
в проекте, агент видит контекст и сможет точечно исправить, не переписывая всё заново.
